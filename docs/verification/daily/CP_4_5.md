# CP-4.5 — accepted-result reading

Stable local verification 2026-10-06. Daily rows link to an internal reading view with the day/filter/density return URL. Comfort/compact density is a URL preference. The detail API resolves current item metadata, actual readiness and the selected accepted production run; pending/quality candidates cannot supply canonical content. The immutable outcome hash and canonical descriptor are checked against the run, source parent, item, canonical schema, artifact kind and VERIFIED state.

Canonical GETs pin that accepted run and return at most four 32 KiB chunks per request, including hashes and offsets. The repository verifies every emitted chunk. The browser checks descriptor identity, ordered ranges, individual SHA-256 values, complete byte length and the entire canonical hash before decoding/parsing/rendering. Only the canonical intelligence document is fetched, not the whole source transcript. Refresh keeps the previous accepted text until a new complete verified document is available; errors do not erase it. Old accepted runs remain readable with a pinned ID, so selection changes cannot mix pages.

The reading view displays full notes/key points, entities/tools and Economy typed rows. Disabled modules are explicit; no replacement summary is generated. Source-speaker/reported-other/unclear attribution, qualifiers and prediction horizons remain attached to their rows. Source issues and partial readiness remain visible. Technical versions sit in a collapsed disclosure. Text renders through React text nodes, including malicious HTML fixtures.

Verification: 37 affected Worker tests PASS across artifacts, Daily and Core API. Added assertions use the actual deterministic production and chunk-production acceptance paths, verify selected descriptors and deny a foreign owner. The multi-chunk artifact regression checks bounded paging and rejects an oversized page limit. Chromium reading E2E PASS checks two canonical pages, source attribution, exact qualifier text, disabled summary, stale accepted text after a corrupted chunk hash and no content on a fresh corrupted read. Seven other affected browser tests ran: six PASS initially and onboarding was repaired/retested PASS; both onboarding tests pass after the repair. Workspace and Worker-test typecheck, affected lint/build/diff PASS. No final Gate U, live provider quality or production CPU qualification is claimed.

The mobile reading screenshot `.local/gui/cp-4.5-reading-mobile.png` was visually inspected: long content wraps, source attribution is distinct, return/source actions are visible, and the reading width is bounded. Final manual accessibility and performance acceptance remain CP-4.8/4.9.

Historical failures: a JSX density control was initially inserted inside an unwrapped conditional; corrected before browser build. The paging fixture had exactly four chunks, so assuming a fifth page was wrong; it now verifies real two-chunk page boundaries plus the default four-chunk bound. The onboarding test ambiguously selected both the receipt and progress-loading status; it now selects the receipt by its expected text. No thresholds/timeouts were relaxed.

Evidence IDs are retained in canonical rows. Their interactive original/helper/time drawer follows CP-4.6, rather than presenting an unavailable Evidence interaction here.
