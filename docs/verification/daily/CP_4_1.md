# CP-4.1 — Daily/date read contracts

Stable local acceptance 2026-10-06. Stage 04 remains in progress; no final Stage handoff or production CPU qualification is claimed.

Owner-only GET `/api/v1/daily`, `/daily/calendar`, `/daily/undated` derive counts from canonical Items and the selected accepted intelligence run. Dates are strict Europe/Warsaw publication dates, including 23/25-hour DST days and leap dates. Unknown publication is separate. READY/PARTIAL/PENDING/BLOCKED/FAILED/REVIEW_REQUIRED are read states, independent of JobState; disabled summary never makes an accepted scoped result pending. An old accepted selection stays readable during reanalysis. Quality diagnostics and chunk children do not override production readiness. Whole-cohort pending is items minus ready, including blocked/failed. Discovery completeness uses the union of actual completed scan windows and preserves gaps/recent incomplete scans, rather than trusting a later watermark. No provider generation, enqueue or write occurs on these GETs.

Pagination signs owner/date/timezone/source filter/cut sequence and the publication/item keyset. A changed cut sequence returns `409 READ_SNAPSHOT_CHANGED`, requiring an explicit refresh instead of mixing revisions. Derived invalidation uses the existing change log; metadata correction stores both old and new publication timestamps. New accepted results retain a bounded, deterministic preview in their immutable outcome; full canonical artifacts and Ledger remain authoritative. Detail and Evidence read APIs follow in the corresponding GUI checkpoints.

Migration mapping: plan's proposed 010 indexes are actual `014_daily_projection_indexes.sql`; existing `items_publication` and selection PK are reused. `015_projection_invalidation.sql` supplies missing notification triggers without adding a Daily content table. Both have immutable ledger hashes; previous migrations remain unchanged. Restore suspends only these notifications in its verified empty isolated target, restores canonical log rows, and recreates notifications in `finally`. Other integrity, auth and immutability triggers remain enabled.
