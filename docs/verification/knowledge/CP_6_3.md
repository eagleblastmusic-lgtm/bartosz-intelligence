# CP-6.3 — reversible identity and authored corrections

Local implementation checkpoint, 2026-10-06. This is not a Stage 06 completion
handoff, production deployment receipt, provider qualification or human review.

## Implemented contracts

- Owner-only merge/split/undo proposals pin every affected identity and alias
  revision. Confirmation atomically records immutable events and membership.
  Incompatible types, foreign owners, cycles, stale revisions and dependent undo
  are denied. Nested changes can be unwound in order. Raw entity IDs and
  Observation rows stay unchanged; current Ledger filtering and future alias
  resolution use effective membership.
- Interpretation/name overlays pin raw target hash, previous value and revision.
  Preview/confirm, author/reason audit, idempotent requests, revision conflicts
  and explicit revert preserve original content and history. Reads verify the
  overlay chain against the original. Ledger presents authored corrections
  separately from the immutable extracted statement.
- Source correction creates a durable owner-authored NORMALIZE job. Original
  accepted source and manifest hashes are pinned before execution. Local
  materialization checks UTF-16 offsets, exact old text, non-overlapping edits,
  cue boundaries and Unicode validity, preserving original timestamps. Verified
  immutable NORMALIZED/SEGMENT_MAP artifacts use logical representation
  `CORRECTED_SOURCE`, producer `owner-source-correction:1` and `original_ref`.
  The accepted NORMALIZE outcome records provenance in the existing run ledger;
  it does not claim to be a captured provider-original transcript.
- Source correction never swaps the selected analysis, mutates Evidence, invokes
  AI or changes original authority. Explicit later reprocessing is CP-6.8.
  Cloud lease is denied for this local workload. Wrong old text leaves the
  owner request BLOCKED/INVALID_INPUT, not accepted. Completion replay is scoped
  to the same worker attempt and exact artifact IDs.
- GUI supports identity preview/confirm/cancel, split/undo, authored annotation
  preview/revert/history, and explicit source correction from verified Evidence.
  Each new identity action requires its own reason. No Markdown/HTML execution
  is introduced. Identity preview includes affected counts and pinned revisions.

- 017: immutable identity events/members, revision/type guards, backup barrier
  and change-log invalidation.
- 018: immutable correction overlays, raw target/old value/revision guards,
  backup barrier and change-log invalidation.

  suspends only their derived notification triggers; validation/immutability
  remain enforced. Existing jobs/artifacts/runs carry source correction data.

  NORMALIZE-scoped `LOCAL_CORRECTION_WORKER_CREDENTIAL`. No credential was
  provisioned and no production process started by this checkpoint.
- Remote deployment remains the previous version. These migrations, routes and
  assets have only local acceptance evidence. No live Gemini/YouTube requests,
  billing, paid fallback or source benchmark rerun occurred here.

  fixture; the implementation continues rejecting stale/mismatched source data.
- Typecheck identified unchecked array indexing and an unsupported library
  declaration for `String.isWellFormed`. Added the bounded index assertion and
  equivalent Unicode surrogate validation without widening compiler targets.
- Artifact client returns `{artifact,text}`, not a string. Fixed the adapter
  destructuring before integration acceptance.
- Identity browser test attempted split with an empty reason after successful
  refresh. Supplied a new reason for each action; the UI guard remains mandatory.
- Format check found two editable tests plus three immutable historical quota
  receipts. Formatted tests and preserved receipts. Restricted sandbox directory
  traversal required rerunning the read-only format check with escalation.
