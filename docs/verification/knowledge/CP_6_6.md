# CP-6.6 — semantic profile compiler and immutable scope registry

Local compiler/registry/editor acceptance: PASS (2026-10-07, Europe/Warsaw).
This is the final record for this logical checkpoint, not a Stage completion
handoff or a Full/Custom provider-quality qualification.

## Implemented

- Economy and Full use the exact existing Wire 1.0 schemas and actual v2
  templates from the verified Master bundle. Custom uses Advanced v2 and a
  deterministic materialized Full subset. The canonical schema remains 1.2.
- Eleven semantic flags; strict no-extra-field configuration and no empty
  profile. Provider/runtime/resource policy are separate. Translation is one
  mutually exclusive scope; history, second pass and validation pass require
  explicit configuration. Each extra pass has a nonempty purpose.
- Custom always contains entity_mentions and source_issues, exact selected
  properties/required, additionalProperties=false and transitively reachable
  definitions only. Contradiction ends contain only selected typed modules.
  No typed modules means exactly an array with null items and maxItems=0.
  The compiler never adds hidden claims. Distinct-record/reference integrity
  belongs to the typed mapper in CP-6.7.
- Schema ID, schema hash, module-scope hash, normalized configuration hash,
  prompt/canonical/enrichment snapshots are materialized before any request.
  Request preview reports a minimum, not an exact quota promise.
- Migration 022_semantic_profiles.sql adds owner-scoped immutable profile
  revisions with schema/prompt foreign keys, author/reason, change notification
  and backup barrier. Compiled schemas extend the existing schema_versions
  catalog; Full/Advanced prompts extend the existing PromptRegistry.
- Profile versions are included in canonical backup/restore. CAS prevents
  skipped/concurrent revisions; identical save replay returns the same version.
- Immutable channel/default assignments use existing config_versions with
  effective_from, explicit apply_to_pending, author/reason and generation CAS.
  New-only eligibility also requires discovery after assignment creation,
  preventing a backdated effective_from from silently overriding pending policy.
- Pending assignment applies to materials without a durable ANALYZE snapshot.
  Existing queued/in-flight jobs retain their original captured profile;
  completed work is never rewritten. Explicit replacement/reprocessing of
  already pinned jobs is part of CP-6.8, not a silent mutation of immutable jobs.
- AnalysisJobs captures the semantic profile independently of PipelineProfile,
  verifies its stored revision on the worker, retains it in child snapshots and
  stores it in the immutable run routing snapshot. Legacy jobs remain readable.
- Owner/CSRF-protected profile preview/version/assignment API. Editor under
  /system/profiles, linked from System and individual monitored channels.
  Master groups: Understanding, Statements, Relations, Representations,
  Additional control. Preview, immutable versions, lost-response save retry,
  default/channel assignment and unchecked-by-default pending choice.

## Capability boundary

Only Economy without optional extra passes can currently be assigned to live
execution. Full/Custom and optional-pass configurations can be materialized and
saved, but activation is disabled in the GUI and rejected by the backend until
their working adapters exist. No fake available adapter, paid route, implicit
pass, quality approval or provider request was introduced. CP-6.7 implements the
Full/Custom runner and typed mapping; CP-6.8 implements optional paths/reprocess.
