# CP-6.4 — Spaces, ReviewState and manual Insights

Local implementation checkpoint, 2026-10-06. Stage 06 formal acceptance and
production deployment remain open. This is not a Stage completion handoff.

## Behavior

Owner-scoped Spaces and memberships organize one canonical Item into many
collections without copying knowledge or evidence. Space create/rename/archive
and restore, membership add/remove, and duplicate membership no-op are explicit.
Inactive Spaces cannot acquire new active memberships; existing members can be
removed. Revisions prevent stale/concurrent writes.

ReviewState independently records saved status, last opening, read timestamp and
the accepted run actually reviewed. New selected accepted runs show “wynik
zaktualizowany”; they never reset saved/read/reviewed fields. Organization reads
are read-only. GUI writes require an explicit owner action.

Manual Insights retain author identity, Item and accepted Observation references.
Refs are owner-scoped and belong to the same Item through their AnalysisRun.
Notes render as inert plain text; Markdown/HTML syntax cannot execute. Notes can
be edited, archived and restored. Immutable organization events retain before /
after snapshots, including old reference sets. No organization operation creates
an AI job or submits a provider request.

The reading view exposes organization and notes on demand. Failed mutations keep
the visible state and draft intact. Retrying a lost response preserves the draft
ID and mutation intent, preventing a second note/Space. Archive uses the saved
note rather than an unsaved edit. Changed run selection refreshes ReviewState.
Bounded lists explicitly disclose incomplete results; editing/archive is disabled
when the reference list cannot be safely reconstructed in full.

## Migration and backup

Plan logical migration `012` organization portion maps to additive
`020_spaces_review_insights.sql` after existing physical migrations 001–019.
Tables: spaces, item_spaces, review_state, insights, insight_observations and
immutable organization_mutations. Composite owner FKs, reviewed-run/ref guards,
backup mutation barriers and change-log invalidation are enforced in D1.

All six tables are in the canonical backup dependency order. Restore suspends
only the derived organization notification trigger. Independent restore verifies
actual Space/membership/review/note/ref/audit equality, retaining Observation
links. No owner credentials or sessions are restored.
