# First owner and deployment

The public login never enrolls the first arbitrary Google user. Administrative access to the selected Cloudflare account creates an expiring, one-use grant in D1; only its SHA-256 is stored there. The private ignored local launcher sends the capability in a POST body to the fixed HTTPS bootstrap endpoint. Do not share the local launcher, capability or prepared secret file. Request observability is disabled so authorization codes, cookies and bootstrap payloads are not ingested as raw request logs.

The server binds the grant once to a browser-bound OIDC state/nonce/PKCE intent marked BOOTSTRAP. Normal intents require the pinned stable Google issuer/subject. Bootstrap still verifies Google's actual RS256 signature, issuer, client audience/azp, time and nonce. It atomically pins one owner, consumes the grant and records a redacted audit event. Parallel claims cannot enroll two owners. After enrollment every bootstrap entry fails closed, including unused grants; normal login resolves the persisted allowlist. The administrative status command copies the verified subject to ignored .env without printing it.

Use the pinned Node/pnpm toolchain. Deployment scripts load .env via Node --env-file=.env, never by printing it. tools/deployment/provision.mjs reuses only resources already recorded in config/deployment.json; it cannot silently take over an unrecorded same-name database/queue. Local fixture wrangler.jsonc remains separate from wrangler.production.json. prepare.mjs migrate checks immutable local SQL hashes and the remote applied prefix, applies only missing migrations, and checks remote quick_check/FKs. Do not retry a partly failed schema migration blindly: inspect the new database and restore/rebuild the explicitly owned empty deployment database if necessary.

prepare.mjs secrets creates a private ignored secrets file and generates the signing secret locally if absent. deploy.mjs uploads those secrets with the official Wrangler secrets-file option and persists only a public deployment receipt. No billing/subscription update is issued. Stage 01 Gate E is the Free account eligibility source; account-settings=standard alone is not evidence of Free eligibility. Current OAuth scope cannot read subscriptions (403), so the attempted current subscription read is UNKNOWN rather than a new Free qualification. Account/project/billing changes require requalification.

After successful deployment, prepare.mjs grant creates a one-hour private launcher. bootstrap-server.mjs serves it on an actual dynamically selected loopback port, with Host/Fetch-Metadata checks, no CORS, no logs, no caching, no framing and form action restricted to the fixed application HTTPS origin and accounts.google.com. Chromium also applies form-action to the 303 redirect destination; omitting Google binds the grant before the browser blocks navigation. This loopback URL only launches the bootstrap; the registered Google callback remains the production HTTPS callback. Run the helper hidden and open its actual local URL for the owner. The owner must deliberately choose their own Google account. prepare.mjs status checks the real result and privately persists the subject. Regenerate a grant after an expired/failed flow; do not weaken state/nonce checks or enroll a guessed subject.

After pinning, prepare.mjs secrets + deploy.mjs may persist the configured subject as an explicit Worker secret. Delete private expired launcher files and stop their local helper when no longer needed. Recovery of credentials is separate from canonical data backup; do not reactivate restored sessions/workers automatically. Stage 02 deployment is a development control plane, not a V1 release.

After verified owner pinning, prepare.mjs control-worker registers the narrow DISCOVER/RECONCILE cloud identity and stores its raw credential only in ignored .env. Repeating it verifies the recorded hash/scopes rather than silently rotating credentials. Then prepare.mjs secrets and deploy.mjs activate Queue execution. Queue commits bounded chunks; cron reconstructs missing wake-ups from durable jobs, so queue expiry does not erase backlog. Neither cloud identity nor Queue hints enable caption extraction or model analysis.
